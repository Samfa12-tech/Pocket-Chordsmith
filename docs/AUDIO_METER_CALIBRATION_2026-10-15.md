# Audio meter reference checkpoint

This extends the existing Core offline analysis used by release mastering and QC.
It does not add a playback engine, native capture path or DSP dependency. Core
remains private 0.2.0 and workspace/repository-only; no npm publication occurred.

## Reproduced discrepancies

Against installed FFmpeg 9.0, the original v2 meter passed 33/40 loudness and 35/40
default true-peak comparisons. A stereo 1kHz fixture measured -14.232237 LUFS while
the reference reported -14.0. Quarter-rate intersample peaks were understated by
about 1.65dB in common-rate fixtures. Original input/log/report files remain in
local validation `meter-calibration/baseline`.

K-weighting now uses the 48kHz coefficient facts from
[ITU-R BS.1770-5 Annex1, Tables1–2](https://www.itu.int/dms_pubrec/itu-r/rec/bs/R-REC-BS.1770-5-202311-I!!PDF-E.pdf),
with an original prewarped bilinear rate transform and the RLB numerator retained.
The prior generic audio shelf/high-pass normalization changed the measurement.
Gating and public API shape remain. This first correction passed 40/40 loudness
cases against the same reference, then 56/56 and final 63/63 with expanded rates.

True peak now uses an original 32-tap Blackman-windowed sinc interpolator at four
times the source rate, with reflected finite-file boundaries. This replaces the
four-point cubic estimate; it does not modify source PCM. A faded 1.2-amplitude
quarter-rate sine has sample peaks below full scale but a known intersample
peak near 1.58dBTP, which the new regression detects.

## External reference and corrections to the experiment

The installed executable is FFmpeg 9.0-full_build-www.gyan.dev. Its complete
SHA256 is stored in the committed numeric reference fixture and local report.
No executable/code was copied into the repository and no dependency, licence,
account or host configuration changed. The filter behavior is documented in the
[official FFmpeg filter reference](https://ffmpeg.org/ffmpeg-filters.html#ebur128).

Loudness uses `ebur128` on the original float32 input. The original default
ebur128 peak is retained in every row. At 192kHz the quarter-rate experiment
returned its sample peak in that mode, so the final independent peak reference
explicitly resamples every rate four times with libswresample and measures the
oversampled peak with `astats`. This is a stated reference method, not a claim
that every reference mode or every reconstruction filter is interchangeable.

An intermediate reference accidentally negotiated integer 16-bit audio into the
resampler through the null output's default encoder. That clipped overshoots
before `astats`: 49/56 comparisons passed and all seven quarter-rate cases failed.
The final run explicitly uses float64 resampling/output, preserving samples
above full scale. The failed run remains in `v3`; it is never counted as passing.

Final filter chain per source rate is recorded verbatim in each reference row:
original `ebur128`, four-times `aresample` with float64, 32-tap filter/cutoff 1.0,
then overall peak `astats`, with a float64 null output. No gain or normalization
is applied. Core and reference consume identical interleaved float32 PCM; every
input has a SHA256. Fixtures are original generated data, not copied music or
physical recordings.

Before freezing the final reference, generated fixture samples were placed on an
exact binary2^-20 grid and signed zero canonicalized. This makes input hashes
insensitive to insignificant Math.sin last-bit differences between runtimes.
The external63-case run was repeated on these final PCM bytes and passed; this
quantization applies only to generated fixtures, never user audio.

## Passed scope and evidence

All 63 loudness and 63 peak comparisons pass across 16/22.05/44.1/48/88.2/96/192kHz.
These include all DAW UI rate choices and native export range endpoints, plus an
extra 16kHz case. Nine fixture families cover silence, 120ms clips, 1kHz tone,
absolute/relative gating, boundary-heavy intersample peaks, faded interior
intersample overload, sparse transients, stereo anti-phase and multi-band phase.

Acceptance bounds were 0.15LU and 0.2dB. Final worst absolute differences were
0.056508LU and0.010227dB. The FFmpeg loudness summary resolves 0.1LU; these bounds
include that quantization. Timing observations are diagnostic only: the slowest
Core analysis in this run was about 351ms for a generated short fixture. Analysis
belongs off the live audio callback; this does not establish UI/worker budgets.

`packages/pocket-audio-core/tests/fixtures/meter-calibration-reference.json`
contains external numeric readings and input hashes, not values generated by the
Core implementation under test. Normal CI checks all 63 cases without requiring
FFmpeg. Parser/control regressions fail on missing/nonfinite/incomplete results,
and analytical counterexamples cover the prior K-weighting and peak errors.
The full Core build/test passes 208/208, including release mastering. No tests
were skipped. Source/share/normalized/event fixtures and all 12 ordinary rendered
PCM hashes were verified unchanged; only their meter metadata was refreshed.
The generic updater also rewrote timestamps and existing normalization metadata;
a preservation guard caught that and those twelve files were restored to their
known clean base before final verification.

Raw reports/logs are retained under local `meter-calibration/` and shared
validation `meter-calibration-*.log`. The final report is
`v3-portable-reference/calibration-report.json`. Versions/method names are v3;
the public `estimated_pending_external_calibration` status remains conservative.
This is scoped reference agreement, not certification, multichannel validation,
listening acceptance or proof of native finishing preview/export parity.

Existing exported/released files are untouched. Future explicit release-master
renders can change because corrected loudness/peak readings influence trim and
limiter safety decisions; reanalyse their exact written outputs. Finish presets,
monitor-only loudness-matched A/B, reversible Apply/Discard/Undo, native output
integration, decoded format parity and broader vocal/live-source acceptance are
subsequent work. No installed DAW candidate or public release was produced here.
