# Native Finish PCM and delivery verification

This extends PR102 source acceptance with real native offline DSP/monitor
integration. It does not establish installed Tauri IPC, physical recording,
device-consumed output, real vocal/live listening, or release readiness.

## Reproduced compatibility gaps

An actual native float32 WAV from the corrected command adapter was rejected by
the public Core decoder (`format=3 bits=32`). Core now decodes IEEE float32 as
well as existing PCM16/24. It retains sub-LSB precision, stereo, negative zero,
over-full-scale and non-finite samples for honest downstream diagnostics. It
does not change the existing PCM16/24 encoders or musical rendering.

The DAW WAV conversion helper also returned a float32 blob unchanged for an
explicit stereo PCM16/no-dither/no-normalization request. Its regression fails
on the former fast path. The corrected fast path peeks only the canonical
44-byte header for genuine PCM16 passthrough; float input receives the requested
conversion. An additional test prevents copying/reading the entire ordinary
PCM16 blob just to confirm passthrough.

## Actual native evidence

The verifier consumes the retained generated fixture from
`scripts/verify-native-godot-route.ts`: arranged Campfire events, generated
recorded-media-path audio, trim/fades/gain, existing low-pass/master compressor
and gain automation. This is original generated test material, not a physical
recording or a claim about vocal quality. It renders Original, tidy and glue
through the actual native WAV worker, then reads the written float files.
Original project data stays unchanged.

The resulting two prepared files pass through the actual native prepared-monitor
renderer and atomic side-change helper, including a reversal during a crossfade.
All 425,127 stereo frames (8.8568125 seconds at 48 kHz) match the analytical
aligned-source/crossfade/ending-fade reference: max error
`4.0978193283081055e-8`, RMS `1.3039068936530938e-9`. Switch snapshots preserve
frame count, producer position and generation. This is producer-clock PCM;
device output/consumption is a separate acceptance gate. After monitor-only gain,
both full passages remeasure at `-30.174001 LUFS` in this fixture.

Seven actual written delivery files are decoded and reanalyzed: stereo PCM16,
PCM24, float32, mono PCM16, PCM16/24 TPDF, and normalized PCM24. PCM errors stay
within their quantization/dither bounds; float32 is exact and all frame/channel/
bit-depth contracts hold. External FFmpeg9 readings pass all seven LUFS and
seven explicit4x float64 SWR/astats true-peak comparisons using the existing
0.15 LU / 0.2 dB tolerances. Worst errors are 0.026009 LU / 0.008178 dB.
Binary SHA256 is retained; FFmpeg is an installed reference tool, not a runtime
dependency, bundled source or licence change.

The normalized file demonstrates why delivery reanalysis matters: sample peak
normalization produces estimated `+0.271217 dBTP` and the actual headroom warning,
while the unnormalized preview has substantial headroom. This candidate verifies
that warning on the actual written file; it does not claim that the export UI
already presents final-delivery QC. Connecting that UI remains follow-up work.

## Reproduction and retained evidence

Run from apps/pocket-daw with explicit local tool paths:

```powershell
npx tsx scripts/verify-native-finish.ts --source-evidence <retained-native-godot-route-directory> --cargo-bin <cargo.exe> --ffmpeg-bin <ffmpeg.exe>
```

The input directory must be the fixture generated by the native Godot route
verifier. Outputs, input hashes, native logs, written WAVs, clock snapshots,
decoded metrics, external logs and summary remain under
`local-artifacts/scratch/validation/native-finish/run-avkZJ0` for this run.
Initial decoder rejection and incorrect helper behavior are retained as failing
counterexamples; a first harness run missing a required asset-name field was
corrected before the successful integration run. No failure is counted as a pass.
